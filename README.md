# bili-sec-timepoint

把 B 站播放器的时间区域改成**只显示还剩多少秒**；点一下时间点，就能在「插件样式」和「B 站默认样式」之间来回切换。

B 站原生只显示 `00:02 / 06:29`，做笔记、对轴、报 bug 时经常需要"还剩多少秒"。装上之后那一整块被替换成一个数：

```
B 站原生   00:02 / 06:29
本插件     387s
```

**直接点一下那个数字**（或者点原生时间的位置），它就切回 B 站本来的样子：

```
默认样式   00:02 / 06:29
插件样式   387s
```

被换掉的不是某一个时钟，而是**整个时间区域**——连中间的 `/` 一起收起来，所以那块地方干干净净只剩一个秒数。

> 点击时间点在 B 站原本是用来弹出「输入时间跳转」小框的。本脚本把这个手势接管了，也就是说**装了脚本之后不能再靠点击时钟输入时间点**。需要它的话，用菜单里的「点击时间点切换样式」关掉接管即可。

---

## 安装

1. 安装一个用户脚本管理器：[Tampermonkey](https://www.tampermonkey.net/)（Chrome / Edge / Firefox / Safari）或 [Violentmonkey](https://violentmonkey.github.io/)。
2. 打开 `bili-sec-timepoint.user.js`，管理器会弹出安装页；确认安装。
   - 也可以把文件直接拖进浏览器窗口，或在管理器的"添加新脚本"里粘贴内容。
3. 打开任意 B 站视频页，控制栏时间那块就会变成剩余秒数。

脚本注册在整个 `www.bilibili.com` 下（不再只挑几个路径），所以从首页站内点进视频也能生效。非播放器页面它什么都不做。

## 使用

| 操作 | 结果 |
| --- | --- |
| 看剩余时间 | 时间区域只剩 `387s`（距播完还有多久） |
| 点击时间点 | 在「插件样式（只剩秒数）」和「B 站默认样式（`00:02 / 06:29`）」之间切换 |
| `Alt` + `C` | 复制当前时间点链接（不用把鼠标移到控制栏） |
| 管理器菜单 | 切换样式、切换剩余/已播、开关显示、切换小数位数、开关点击接管、开关 Alt+C、立即复制 |

复制出来的链接长这样，`t=` 是向下取整的秒数，原来的 `p=`（分 P）等参数都会保留：

```
https://www.bilibili.com/video/BV1GJ411x7h7/?p=2&t=137
```

> 复制链接用的始终是**已播**的秒数（也就是"第几秒"），和读数显示的是剩余还是已播无关——分享给别人时，`t=` 的含义永远是"从这一秒开始播"。

> 找过这个脚本的话可能记得，早先版本是"点击秒数 = 复制链接"。现在点击被切样式占用了，**复制挪到了 `Alt`+`C` 和菜单项上**，功能没有丢。

### 设置

所有设置通过用户脚本管理器的菜单命令调整，存在 `GM` 存储里，跨页面保留。默认值：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 显示秒数 | 开 | 总开关；关掉后 B 站时钟立刻还原 |
| 样式 | 插件（只有剩余秒数） | 在「插件样式」和「B 站默认」之间切换 |
| 模式 | 剩余秒数 | 在「显示剩余秒数」和「显示已播秒数」之间切换 |
| 小数位数 | 0 | `0`–`3` 位，循环切换；`0` 就是 `387s` |
| 点击时间点切换样式 | 开 | 关掉后不再接管 B 站时钟的点击，把"输入时间跳转"还给它 |
| Alt+C 复制时间点 | 开 | 关掉后不影响页面原有的快捷键 |

关于「点击时间点切换样式」为什么默认开启：这比在控制栏里再塞一个按钮干净，而且点击的目标就是你想切换的那个东西本身。代价是 B 站原先"点击时间输入跳转"的功能被屏蔽——在意的话关掉这一项就行。

脚本对 B 站自己元素的改动只有"隐藏"这一种，隐藏过的节点都打了 `data-bst-hidden` 标记，所以还原时不会误伤 B 站自己设置的样式。

## 读数为什么和 B 站原生时间长得一样

把 `00:02 / 06:29` 换成 `387s` 之后，最容易出问题的是**读数看起来不像原来那个时钟**——颜色偏灰、位置偏了一截。脚本从两个方向避免这件事：

- **位置**：读数不是塞在时间区域旁边的兄弟节点，而是**放进时间区域内部**，占的正是原来 `00:02` 那个槽位。区域本身留在布局里（只是里面的两个时钟和 `/` 被隐藏），所以控制栏的 padding、高度、垂直居中都还在，读数是由**和原来完全相同的规则**摆放的。
- **颜色**：播放器给时钟上色用的是指向子元素的选择器（类似于 `.bpx-player-ctrl-time-current{color:#fff}`），这种颜色**不会**被子元素继承，所以光"待在盒子里"还不够。脚本改为运行时从活的时钟元素上读 `color` / `opacity` / `font-size` / `font-weight` 再贴到读数上，而不是写死一个色值——这样换皮肤、换主题、进出全屏时缩放变化都能跟上。

颜色和透明度是通过 CSS 变量传的（而不是内联 `color`），所以鼠标悬停时读数仍然会变蓝提示"这里可以点"。

## 它是怎么找到时间元素的

B 站的播放器控制栏是前端渲染的，而且前后换过至少三代类名（`bilibili-player-*`、`squirtle-*`、现在的 `bpx-player-*`），清晰度切换、全屏进出时整条控制栏还会重新渲染。所以脚本不写死一个选择器，而是按顺序尝试三层：

1. **已知的精确类名** —— 覆盖三代播放器的 `.bpx-player-ctrl-time-current` / `.bilibili-player-video-time-now` / `.squirtle-time-now` 等，当前进度的和总时长的分别有各自的选择器表。能认出整个时间盒子（`.bpx-player-ctrl-time`）时，读数就放进这个盒子里、把盒子里原有的内容整体隐藏，`/` 也就跟着一起没了。
2. **结构启发式** —— 在控制栏范围内找出**文本长得像 `mm:ss`（或 `hh:mm:ss`）的叶子节点**，第一个当进度、最后一个当总时长。类名改掉时靠这层兜底；认不出盒子就退化成分别隐藏两个时钟和中间的 `/`。
3. **浮层兜底** —— 如果一个时钟节点都找不到，就在播放器左下角浮一个半透明读数，仍然可用。

点击接管也用同一套解析结果：捕获阶段挂在 `document` 上的 `click` / `mousedown` 监听器先于 B 站绑在时钟上的处理器执行，命中时间区域时直接 `stopPropagation()`，所以它的「输入时间点」小框根本收不到事件。

一个 500 ms 的心跳循环负责：控制栏被重新渲染后把读数重新插回去、视频元素被替换后重新绑定、以及检测 B 站站内（SPA）切视频并重置状态。另外全屏切换和窗口缩放时会重新同步一次时钟外观。

## 离线自测页

`test/mock-player.html` 是本地的可视化验证页，**不需要服务器、不需要装脚本管理器**：直接用浏览器打开这个文件，选一个本地视频，然后在三种布局之间切换。

| 布局 | 模拟的情况 | 预期 |
| --- | --- | --- |
| modern | 现在的真实 `bpx-` 类名 | 时间区域里只剩一个 `387s`，颜色/位置和原来的时钟一致 |
| renamed | 类名全被改掉 | 靠文本启发式仍然找得到，两个时钟和 `/` 各自被隐藏 |
| bare | 完全没有时钟节点 | 出现左下角浮层读数 |

页面上还有「检测 `resolveTimeNodes()`」「复制当前时间点」「模拟播放器重渲染」三个按钮，外加两个对比开关：

- **样式：插件 / B 站默认** —— 等价于点时间点，用来直观比对两种样式
- **读数：剩余秒数 / 已播秒数** —— 实时切换两种模式

页面里的模拟时钟也挂了一个普通的 `click` 处理器：如果脚本没能拦住事件，日志里会出现一行 `!! bilibili's own click handler received the event`。这是点击接管最直接的验证。

「检测」按钮的输出里有一行 `our readout style`，会打印脚本从原生时钟上抄到的颜色/透明度和字号。如果这行是 `(inherited)` / `(default)`，说明没读到原生样式，读数就只能靠 CSS 继承——在真实页面上把你看到的这行发出来即可。

## 自动化测试

```bash
npm install --cache ./.npm-cache   # 见下方说明
npm test
```

用 [jsdom](https://github.com/jsdom/jsdom) 把脚本注入到三个仿造的播放器 DOM 里跑，覆盖 145 条断言：调试入口是否真的发布到页面窗口、控制台启动横幅与降级提示、格式化、剩余/已播两种模式的换算、时间点链接构造、启发式正则、读数在时间区域里的落位、原生时钟的隐藏与还原、颜色/透明度/字号的抄取、点击切样式与事件拦截、Alt+C 复制、菜单命令、每个设置项、控制栏重渲染后自动恢复、SPA 导航，以及**一整组「网页全屏安全」回归测试**（正常玩家不被改样式、控制栏重建不误触发浮层、浮层期间的内联 `position` 会被还原、逃生命令能清干净）。

> **为什么装依赖要带 `--cache ./.npm-cache`**：如果系统 npm 缓存目录不在当前工作区、且当前环境对它有写限制，默认 `npm install` 会报 `EPERM`。把缓存指到工作区内即可。已经能正常 `npm install` 的环境直接 `npm install` 也行。

## 装了没反应？按这个顺序查

**第一步：确认脚本到底跑了没有。** 打开 F12 控制台，过滤 `bili-sec-timepoint`。正常情况下一定有一行：

```
[bili-sec-timepoint] v1.3.1 已加载，调试入口：__biliSecTimepoint
```

- **有这行** → 脚本在跑。如果读数没出现，后面应该还跟着一条说明原因的提示，照它给的命令查。
- **没有这行** → 脚本根本没执行，看第二步。

脚本所有输出都以 `[bili-sec-timepoint]` 开头。控制台里那些 `bili-fe-fp` / `bili-fe-mirror` / `白屏检测是否正常` **是 B 站自己打的日志**，跟本脚本无关。

**第二步：确认篡改猴有本站权限。** 点篡改猴图标，如果弹出「**篡改猴没有访问此页面的权限**」，脚本就不会被注入（脚本列表里那一条是灰的）。解决：

1. 地址栏进 `chrome://extensions`
2. 找到**篡改猴** → 详情
3. 把「**网站访问权限**」从"点击扩展程序时"改成「**在所有网站上**」
4. 回 B 站刷新页面

另外两个常见原因：脚本在管理器里被停用了（图标菜单顶部那个开关要是「已启用」）；或者刚改完权限/设置但没刷新页面。

**关于 `__biliSecTimepoint is not defined`：** 带 `@grant` 的脚本在篡改猴里跑在沙箱中，如果只写 `window.__biliSecTimepoint`，有时控制台（它在页面上下文里求值）看不到。1.1.1 起脚本会**同时**写到页面窗口上（`unsafeWindow`）来避免这个问题。如果仍然报这个错，那几乎可以肯定是脚本压根没运行——回到第二步。

## 它会不会弄坏播放器？怎么自查

脚本原则上只插入自己的元素，另外接管时间区域的点击。**唯一会改动 B 站自己元素的地方是隐藏时间区域里的两个时钟和 `/`**（插件样式下总是如此，切回默认样式或关掉总开关都会立刻还原）；时间区域这个容器本身始终留在布局里，脚本不碰它的 `display`。

不过 1.2.0 修掉了一个确实会弄坏播放器的 bug，值得记一笔，因为它正是「网页全屏」：

早期版本在「找不到时钟节点、改用浮层读数」时，会给播放器容器写上**内联的** `position: relative`（浮层是 `position:absolute`，需要一个定位祖先）。问题在于**内联样式优先级高于样式表**，而 B 站的网页全屏恰恰是靠把同一个容器切成 `position:fixed` 实现的 —— 于是一个残留的内联 `position` 会让网页全屏**永久失效**，哪怕浮层早就撤了。触发它的还不是「播放器真的没有时钟」，而是切清晰度 / 进出全屏时控制栏被重建、时钟节点短暂消失的那一两拍。

1.2.0 的两处修法：

- 内联 `position` 的作用范围严格绑定浮层的生命周期，原值记在 `data-bst-positioned` 里，浮层一撤立刻还原；
- **时钟短暂消失不再触发浮层回退** —— 必须连续 6 拍（约 3 秒）都找不到才降级，把整类「渲染过渡期误判」挡在外面。

### 一条命令看清脚本改了什么

脚本对 B 站自己元素的所有改动都打了 `data-bst-*` 标记，所以清单是完整的：

```js
__biliSecTimepoint.describeMutations()
```

返回 `hiddenClocks`（被隐藏的原生时钟与 `/`）、`repositionedRoots`（被改过 `position` 的容器）、是否正在用浮层、以及当前连续未命中的拍数。

**播放器有功能坏了的话，按这个顺序查：**

1. **确认是不是脚本干的。** 用篡改猴菜单里的「显示秒数」把脚本关掉（会立刻撤销所有改动），刷新页面再试那个功能。功能恢复 → 就是脚本。
2. **是脚本的话，让它自己撤。** 在控制台跑：
   ```js
   __biliSecTimepoint.revertDomMutations()
   ```
   它会撤销对 B 站 DOM 的全部改动并返回被撤销的清单。跑完再试一次那个功能；如果好了，把返回的清单发我。
3. **切回「B 站默认」样式再试。** 那是唯一会碰原生元素外观的地方（菜单第一项，或者直接点一下时间点）。
4. 都不行就停用脚本、刷新，确认问题是否本来就存在（B 站自己也经常抽风）。

## 已知限制

- **选择器未经真实页面验证。** 脚本的开发环境无法启动无头浏览器，也无法访问 B 站前端渲染后的控制栏 DOM，所以上面的类名和启发式是依据公开的播放器结构写的，理论上覆盖了三代类名，但**没有在线上页面逐条核对过**。脚本因此把"找不到就降级"设计成了默认行为，而不是直接失效。
- 如果在你的浏览器里读数没出现、或位置不对，请在控制台运行：

  ```js
  __biliSecTimepoint.resolveTimeBox()     // 整个时间区域认出来了没有（认出来就把读数放进这个区域）
  __biliSecTimepoint.resolveTimeNodes()   // 看命中了哪个节点、命中了 null 还是元素
  __biliSecTimepoint.guessTimeNodes()     // 看启发式找到了哪些候选
  __biliSecTimepoint.describeMutations()  // 脚本到底改了 B 站哪些元素
  ```

  `resolveTimeBox()` 返回元素或 `null`；`resolveTimeNodes()` 和 `guessTimeNodes()` 返回 `{ current, duration }` 或 `null`。据此可以补一条精确选择器到 `SELECTORS.timeBox` / `SELECTORS.current` / `SELECTORS.duration`。
- **`.bpx-player-ctrl-time` 这个类名同样没在真实页面上核对过。** 它是"整个时间区域"的猜测值；如果猜错了，脚本会退化成分别隐藏两个时钟和中间的 `/`——效果一样，只是读数落在区域旁边而不是里面，位置可能略有偏差（`describeMutations().hiddenClocks` 会显示两条时钟加一条 `/`）。
- **读数的外观是从原生时钟上"抄"来的。** 如果 B 站某天用图片或伪元素来画时钟，`getComputedStyle()` 读不到可抄的颜色，读数就会退回 CSS 继承的颜色。自测页「检测」按钮的 `our readout style` 一行能看出抄到了什么。
- **被脚本接管的点击不会再传给 B 站。** 也就是说装了脚本之后，点击时间区域不会弹出"输入时间跳转"。想要那个功能就在菜单里关掉「点击时间点切换样式」。
- **小数位数的四舍五入是二进制浮点行为。** 读数用 `toFixed`，在恰好落在 `.x5` 边界上的值（例如 65.05）会向下取整。这是有意为之：结果可预测、不引入 epsilon 修正；而且这种值在播放中只会出现一瞬。
- **剩余秒数在视频元数据加载前显示 `--`。** 因为这时 `video.duration` 还是 `NaN`，算不出剩余时间；`loadedmetadata` 一触发就会显示正常数值。
- 只处理 `<video>` 型的播放器，不处理直播。
